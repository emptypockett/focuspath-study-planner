# Common App activity — how to describe FocusPath honestly

The project files are created, but an admissions activity should describe your own real work, not just the existence of generated starter code.

## Draft activity name
FocusPath — Student Study Planner

## Draft position
Student Developer (use only if you personally continue development and understand the code)

## Draft description (150-character limit — verify in the Common App field)
Built a web-based study planner with task management, a focus timer, and progress insights using JavaScript, HTML, and CSS.

This describes the current feature set. Before submitting, make sure you have personally run, tested, and can explain the code. If you only made small changes, describe your role more narrowly.

## Details worth documenting
- Which features did you personally implement or modify?
- What bug did you encounter and how did you solve it?
- What feedback did real testers give you?
- What did you change because of that feedback?
- How many people actually tested or used it? Count only real people.
- How many hours did you personally spend? Track honestly.

## A useful reflection structure
1. The problem you noticed.
2. Why you chose to build this solution.
3. One technical challenge and how you approached it.
4. What changed after testing.
5. What you would build next.

Never invent users, impact, awards, hours, or outcomes.
